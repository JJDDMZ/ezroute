# EZ Route 使用指南

EZ Route 根据 USB 与 Wi-Fi 的可用状态更新 Clash 出口。iPhone 需开启个人热点，随身 Wi-Fi 等设备需开启 USB 供网；Clash Verge Rev 需要开启 TUN。

## 首次配置

1. 运行 `./script/install.sh`，打开 EZ Route。
2. 用 USB 连接 iPhone 或随身 Wi-Fi，在“设备与网络 → 指定 USB 出口”中选择设备。iPhone 需先信任这台 Mac。
3. 使用无线连接时，连接手机热点或随身 Wi-Fi，允许读取 Wi-Fi 名称，再点击“信任当前无线连接…”。
4. 开启“自动路由”，在“概览”核对当前模式。

应用会安装所需的 Clash 全局扩展脚本并保存备份。已有自定义脚本需要先检查兼容性；遇到提示时保留原脚本并检查提示内容。公开版本的学校例外使用示例值，见[校园配置](campus-profile.md)。

USB 供网需要 macOS 可识别的以太网接口和可用 IPv4 地址。原有 iPhone 设备选择和无线信任记录保留；更换供网设备需选择新的 USB 出口。无序列号的设备更换 USB 端口或扩展坞后，可能需要重新选择。

信任的无线连接支持 WPA／WPA2／WPA3 个人网络，按名称与安全类型匹配。使用独有名称，改名后重新添加。

## USB 系统 DNS

0.2.20 在核验 Clash 的目标配置后，将所选 USB 网络服务的系统 DNS 指向运行中 TUN 的 DNS 地址。此项修复 USB 设备的局域网 DHCP DNS 绕过 Clash、导致普通请求失败的问题；代理节点、分流规则和校园 Wi-Fi DNS 保持原有逻辑。

首次修改需要 macOS 网络设置授权。拒绝后，后台不会反复弹窗；重新开启自动路由或点击“检查路由”可重试授权。应用按网络服务 UUID 定位，DNS 地址取自实际 TUN IPv4 子网。

修改前会保存原 DNS 字典，包括手动服务器和搜索域；原值为空时恢复为 DHCP 自动 DNS。停用自动路由、正常退出、TUN 关闭、Clash 控制接口不可用或不再使用该 USB 出口时，应用尝试恢复；异常退出后在下次启动时恢复。用户或其他程序已修改 DNS 时，应用保留外部设置。

恢复记录保存在 `~/Library/Application Support/dev.ezswitch.app/usb-dns-recovery.json`，目录权限为 `0700`、文件权限为 `0600`。此文件包含本机恢复数据，不应分享或上传。恢复失败时应保留记录，在“检查路由”中允许授权并重试。

强制退出、断电或系统崩溃时不能保证即时恢复；需要重新打开应用。当前没有独立恢复守护程序。DNS 接管不提供系统级零泄漏保证，也不代表微信朋友圈等所有应用都已通过验证。

## 诊断与监测

连接列表展示目标、策略出口与流量。用量按应用运行期间的接口记录汇总。网站响应检查 HTTP 状态与耗时；实际出口检查在授权后采集测试包头，将接口与测试目标关联。

HTTP 403 或 405 是网站返回的响应，结合实际出口结果判断路由。测试数据只覆盖本轮请求。

## 退出与升级

使用应用菜单中的“退出”，等待路由调整完成。指定 USB 出口在线时继续使用该出口；只有 Wi-Fi 时使用直连并停用代理，即使该无线连接已受信任；离线时阻断 Clash 请求。无法完成调整时，应用会继续运行并提示处理办法。

需要继续通过信任的无线连接使用代理时，保持应用和自动路由运行。

安装器会备份旧包。原 bundle identifier 与偏好键保留；首次改名升级后，用“通用”中的“登录时启动”开关重新登记已有登录项。

## 手机切卡

需要双卡自动化时搭配 [EZ SIM](https://github.com/JJDDMZ/ez-sim)。手机快捷指令与 Mac 路由各自运行。
