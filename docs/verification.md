# 验证说明

## 离线检查

运行 `./script/verify-routing.sh --offline`。入口依次执行 Swift、Python、Node.js、构建和签名检查，在临时目录保存整轮日志。

公开版本首次检查覆盖 Swift 223、Python 143 和 Node.js 15 项测试。Swift 与本机 Unix socket 测试需要 macOS；测试中的网络交互使用本机回环服务。

0.2.19 新增 6 项回归，覆盖通用 USB 设备标识、iPhone 旧标识兼容、无序列号设备，以及随身 Wi-Fi 的 USB／无线代理与 DNS 绑定。真机驱动识别、插拔恢复和物理出口需在具体设备上验证。

0.2.20 新增 14 项 DNS 管理回归，覆盖 DHCP／手动 DNS 与搜索域恢复、持久化恢复记录、外部修改、授权拒绝、提交成功但应用失败后的重试、服务身份变化、TUN 地址校验、异步期间 USB 变化及 TUN／控制接口不可用。系统 DNS 的实际授权和应用由 macOS 执行；离线测试不能代替这些实机操作。

ZTE F50 Pro 通过 USB 供网并同时连接校园 Wi-Fi 时，修复前显式代理请求成功，普通 TUN 请求失败。仅接管所选 USB 服务的 DNS 后，指定 Google 请求恢复；安装 0.2.20 后，用户确认 Google 搜索、ChatGPT、B 站首页和视频正常使用。该结果限定于此设备、连接组合和业务，不构成长期稳定性或物理出口零泄漏证明。

新版拔线／停用后的 DNS 恢复尚未完成实机验收。微信朋友圈缩略图在断开校园 Wi-Fi 后部分恢复，大图仍慢或失败；该问题保持开放，未包含未部署的 fake-IP 候选修改。原始网络、设备和连接记录保留在本地，未随源码发布。DNS 接管与恢复方式见[使用指南](setup.md)。

## 支持的配置

当前转换器支持 `trojan`、`vmess`、`vless`、`ss`、`ssr`、`http`、`socks5` 和 `snell` 节点，以及内联节点选择组。提供器、额外监听器、隧道和链式代理由结构检查拒绝。未知结构应先扩充校验与测试，再启用自动分流。

应用的“网站响应”检查 HTTP 结果，“实际出口”通过测试抓包检查物理接口。校园例外配置见[校园配置](campus-profile.md)。

## 出口保护范围

软件收到网络变化事件后才重新配置 Clash。无线连接从可信网络切换到校园网时，物理接口可能仍是 `en0`，旧授权撤销前存在窗口。应用崩溃后缺少独立授权撤销机制；关闭或绕过 TUN 后，应用无法提供同等保护。当前实现不能保证所有情况下代理流量都不进入校园网络。

正常退出时，只有 Wi-Fi 在线会转为直连，包括信任的无线连接。退出后的代理不可用符合当前退出策略；需要无线代理时保持应用运行。

## 已知问题

- 国内直连规则去重尚未区分规则类型与优先级，某些订阅中的同名规则可能影响前置规则。
- `EZRoutingTool` 的审计路径尚未完整沿用 Apple 偏好。
- 恢复依赖应用与 Clash；切换瞬间、应用崩溃后的独立阻断，以及部分睡眠场景仍需实机验证。
- 历史 `--guided` 流程依赖私人安装证据和旧设备键。公开版推荐使用离线入口及应用内定向诊断；该历史流程需要先适配本机证据。

上述问题保留为后续工作。离线检查通过与指定请求的实测结果分别记录。
